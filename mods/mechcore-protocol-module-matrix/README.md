# 机核协议：模组矩阵（组件） / Mechcore Module Matrix

随机核协议构建和发布。项目与安装入口见[机核协议](../mechcore-protocol/README.md)。

本组件提供模组、节点、摆放效果与持续成长。需要 NicoKobo Forge 的协议 1 和固定能力 API 1。 约束及待办见[组件设计](../../docs/design/MODULE_MATRIX.md)。

## 本批内容

沿用 `nicokobo.mechcore_protocol.module_matrix` 身份，包含 **19 件物品、19 张原图标和 6 种摆放效果**，通过轻量客户端使用 Forge 前置，不静态引用其他 Mod 程序集、MelonLoader 或 Il2CppInterop。

| 类别 | 内容 |
| --- | --- |
| 6 件固定模组 | 平衡、流水线、精工、稳态、高功率、检测；保留原数值和含缺口的形状 |
| 3 件连续模组 | 连续加速、连续节能、连续校准；分别提供性能、效率、质量成长 |
| 5 件节点 | 性能转换、节能转换、质量转换、隔离、学习加速 |
| 4 件有效机器模组及 1 件停用旧物品 | 渗透、自动供水、市场追踪、解码缓存；批量烧制仅供旧档读取 |
| 6 种摆放效果 | 角落挂载、留空增强、紧邻增强、独立安装、底部挂载、右侧挂载；效果不是单独物品 |

合成扩展 M04／M05／M06 引用的连续节能／加速／校准模组 ID 已由本候选注册。**同时安装并启用两个正式版候选后**，这三条配方有对应材料提供者；原料和数值保持不变。两包通过共享库交换 K02 额外配方，实际组合加载与制造仍待游戏内验收。

合包 manifest 只声明主入口 `MechcoreProtocol.dll`，以 `Prerequisites` 声明独立 Forge。五种固定节点能力在 Forge 私有能力表中登记，不进入原版随机词缀目录；已删除随机候选列表的 IL 补丁，`Capabilities` 为空。供货使用官方顾客生成事件。

## 行为

连续加速和节能起始 +8、每次有效工序 +4、总上限 +32；连续校准起始 +4、每次 +2、总上限 +16。相邻学习加速节点使单次成长量翻倍，同类不叠加，也不提高上限。成长由原生工序完成回调触发；工作日写入物品标签，过夜在全部原生机器循环之后检查闲置。闲置一天回落一步，并保存当日结算标记，避免同一天重复回落。读取已有工作日标记，不推测旧物品缺失标记之前的工作记录。

认知涡轮接口只识别当前真实持有且数量为正的植入物 `nicokobo.aug.cybernetic.cognitive_turbo`。持有时连续模组总上限提高 50%：加速／节能 +32→+48，校准 +16→+24；普通工序同样适用。原生自学习按该件模组原有上限 ×1.5 向下取整，不改写原生上限标签。失去植入物后保留已获得的成长，停止突破普通上限，闲置回落照常。

持有认知涡轮时，一次性、高级和超科技增压器（`turbo_booster`／`turbo_booster_adv`／`turbo_booster_hypertech`）真正完成工序才将本次成长补足至普通单次的 2 倍；与相邻学习加速节点组合为 4 倍。按使用前快照补足，多批加工已经获得的成长不重复叠加，拒绝加工不额外成长。提示显示有效上限和普通／加速器成长量。植入物本体和获取路径由机械飞升内容包提供，本包按真实持有状态读取，不重复注册植入物。

节点按“先隔离、再转换”计算，转换逐个来源取整。同一来源由先放入的节点处理，安装顺序保存到原物品标签，移除后再次放入重新排队。节点以实际占用格判断相邻，不以外接矩形判定。读档完成后重新计算宿主，重复计算不会叠加临时值。学习加速也支持携带原生自学习词条的模组，并遵守该件模组的有效上限。

摆放效果保留 +30% 角落、每个不同空邻格 +4%、每件不同相邻模组 +10%、独立 +50%、底部／右侧各 +20% 的规则，只放大正向基础属性。两个位置词条先合计百分比再取整；紧邻和独立互斥，舱内封闭缺口不算外边缘。两次原生扩舱成功后立即重算，不移动物品、不改变节点顺序，与读档使用同一重算流程。开启时六种词缀仍进入原版随机目录；关闭时保留私有显示定义和旧槽位。五种固定节点能力始终独立于原版随机目录，沿用已有效果 ID 和存档标签。

机器专用模组仅能装进对应机器，保留原有模组准入。渗透模组每件额外滤除各类可处理污染物剩余量的 25%，多件依次乘算并回补等体积水；与基础净水共用当前质量对应的原生总纯度上限。剩余额度按全部液体组分及原生整数取整计算，已达上限时不再附加去污；实际去污为零时不扣电、不成长，机器提示和物流终端均使用同一原生上限。自动供水优先补给相邻净水器里的容器，再补给其他相邻容器，使用原生液体转移。

市场追踪由完好的警报系统每晚尝试一次，以性能修正 25% 基础概率并写入夜间日志。解码缓存保留首个已安装缓存模组的选择规则，只在原生解码确实产生目标物品且移除输入后记录目标；相同目标工序速度 ×2，工序结束或异常时恢复原速度，面板数值不永久改变。

S26 批量烧制与熔炉整批容量补丁已移除。S26 仅保留物品工厂、稳定 ID 和原占格供旧档读取，不再生效、允许新安装或参与供货；已有槽位中的实物不移动。原有连续加工及连续加速、节能、校准模组保留。

原版和 Matrix 的基础／稀有／功能性分类保留，原生商品交由游戏定价，Matrix 自家商品独立定价。原生旧实例只有带本 Mod 价格来源标签时才撤销本 Mod 的历史差额，并停用该标签，保留品质和其他价值；没有标签的实例不改价，重复读取不重复撤销。

## 获取与配置

五种基础固定模组进入原生总模组表和一阶模组表，每件相对权重 0.08；高功率、连续模组、节点和机器专用模组不加入拾荒表。杰克逊夜店每次生成库存额外抽取两个不同品种，先按基础∶稀有侧 2∶1 选档，再在档内等概率选择；功能性模组属于稀有侧。原有商品名额保留，容量与实际放置由原生上架方法处理。

现有 18 件有效模组／节点接入小偷（Thief）和发明家／杰克逊（Inventor）的额外供货，按类别开关筛选。与同池其他已接入内容共享总 Mod 相对权重预算 **0.25**，不是每包各占 0.25。既有夜店额外两件商品规则保留，供货接口不重复给这两件加货。

向合成扩展 K02 提供“任意基础模组／节点 ×2 → 随机稀有模组／节点 ×1”配方，可用原版或 Matrix 材料，同种、混搭均可。默认类别开启且物品实际注册时，稀有产物池为 **13 种**；关闭类别和未注册物品从池中排除。升级按明确的基础／稀有 ID 分类，排除功能性模组、特殊核心、损坏品和封顶核心；K02 手册通过共享接口显示该配方。

矩阵不再贡献原生熔炉配方或批次驱动。其他机器仍通过 Forge 公共机器接口与[自动化物流](../automated-logistics/README.md)对接真实库存和生产事务。

官方配置面板提供固定模组、摆放效果、连续模组、节点和机器模组五个开关，默认开启，修改后重启游戏。关闭类别时保留原物品定义、成长和槽位，停止新掉落、供货、升级产出及效果。本候选不读取或改写旧 Melon 配置。

## 后续迁移与验证边界

- K02 稀有升级、额外供货及认知涡轮接口已接入；认知涡轮效果由机械飞升的真实植入物提供者激活。物流生产机会由共享过夜 flush 先结清，再进行矩阵闲置回落，避免因内容包订阅顺序而提前回落。
- 多包共用的 G 键查询会列出 K02 稀有升级配方；开关／实际工厂可用性参与动态目录筛选。
- 官方本地化资源覆盖 19 件物品名称、5 件机器能力和 11 个效果的名称／说明，共 46 个键。中英两套文本覆盖 `en` 和游戏各 `zh` locale，提示与原生效果目录按当前语言刷新。
- S11 定向投影保持原源码的隐藏状态，不注册为可取得物品。
- 不自动转换 Demo 存档或旧库存图。稳定 ID 与物品标签的保留不代表旧存档可直接互通。
