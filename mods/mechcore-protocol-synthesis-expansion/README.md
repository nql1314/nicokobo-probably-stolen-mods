# 机核协议：合成扩展（组件） / Mechcore Synthesis

随机核协议构建和发布。项目与安装入口见[机核协议](../mechcore-protocol/README.md)。

本组件提供工业材料、加工机器、制造终端配方、义体与功能设备。需要 NicoKobo Forge 协议 1。 约束及待办见[组件设计](../../docs/design/SYNTHESIS_EXPANSION.md)。

## 本批启用的内容

保留原物品、机器和配方 ID，注册 **25 个物品定义、27 张图标（含两张状态图）与 30 条配方**：

| 内容 | 数量与范围 |
| --- | --- |
| 材料／组件 | 9 种：石英原料、硅、钛矿料、钛合金、精密零件、高级电路、控制芯片、电源调节组件、机械核心 |
| 机器 | 本包 3 台：材料精炼机、机电工作台、精密装配机；另使用 Forge 的全域制造终端 |
| 义体 | 6 件：AI 核心、睡眠压缩模块、动能回收、钛合金外骨骼、精细动作辅助器、高科技眼镜 |
| 功能设备 | 机器猫、义体保管箱、拾荒机器人、便携采矿钻 |
| 配方手册 | 3 本：材料精炼手册、合成手册、义体目录；原生 UI 展示当前配方或已启用内容的十四件义体与脑机接口 |
| 加工配方 | 16 条：7 条普通／高炉炼锭路线及 9 条材料、组件、普通电子元件与空捕鼠夹配方 |
| 玻璃回收 | 4 条：材料精炼机回收空啤酒瓶、玻璃刀、碎玻璃和酒瓶，产出石英原料；不同原料不能混凑 |
| 全域制造 | 10 条：六件义体和四种功能设备；M04–M06 由模组矩阵提供连续模组材料 |
| K02 外部升级 | 模组矩阵可用时增加 1 条：任意基础模组／节点 ×2 → 随机稀有模组／节点 ×1 |

机器使用原生机器窗口、电池槽和模组舱，库存顺序保留电池／模组／投料／产物／便签。三台加工机性能每满 100 增加一批；**全域制造终端每晚只生产一批**，效率仍影响实际耗电。批次先放置完整产物，再提交材料与电量，失败时补偿已变动资源；原料不足、空间不足或扣电失败不会视为生产成功。

全域终端 `nicokobo.forge.machines.universal_manufacturing_terminal` 由 Forge 提供并执行生产，本包通过客户端贡献其中 10 条配方。M04／M05／M06 分别需要[模组矩阵](../mechcore-protocol-module-matrix/README.md)的连续节能／加速／校准模组，需要同时安装并启用该提供者。未改写原配方或替换材料；实际组合制造仍待游戏内验收。缺失提供者时手册会提示。

精炼机区分普通与高炉模式，优先一份矿石配废料，原料不足时再选择其他可执行配比。高级产物仍优先于同机炼锭；每批重新读取材料。玻璃回收与精炼共用 K01 的电量、性能批数和完整产物空间检查，不再扩展原版熔炉。

K02 升级沿用矩阵的原配方 ID，接收同种或混搭的真实基础模组／节点，并可跨堆叠扣料。默认可用稀有池共 13 种，排除功能性模组、特殊核心、损坏品和封顶核心；禁用类别或缺失工厂会实时移出候选池。升级走 K02 原有生产事务，基础耗电为 15，效率仍影响实际耗电；空间不足、原料不足、产物工厂异常或扣电失败时不提交。合成手册动态显示此配方，固定配方仍为 30 条，schema 26 将原玻璃回收目标迁到 K01。

硅、钛合金和加工组件保留纯度规则，高级电路保留独立品级。当前正式版完美纯度 `ValueMod=200`，对应总倍率 300%；生产价值归一化已按当前游戏的六级纯度表核对，避免零质量加工额外放大价值。使用原 `NICOKOBO_FORGE_PRODUCTION_BASIS_V1` 标签格式；与食品加工的价格恢复在离线检查中保持一致，实际组合加载仍待验证。

石英、钛矿料和机器接入原掉落来源；杰克逊夜店出售矿料、按原概率提供机器及缺失手册，从第 22 天起可提供尚未持有的硅。新局发放三本手册，空间不足时可在夜店补购。

额外 NPC 供货接入石英／钛矿料及第 22 天起的其他加工材料，与食品加工、模组矩阵共享一次总 Mod 相对权重预算 0.25。矿工整批只抽一次，保留原版／石英／钛为 70%／15%／15%，原矿掉落权重仍为 125；指定设备与固定商品保留原生供货流程。

通过 [Forge 公共接口](../shared/Nicokobo.ContentInterop/README.md)公开本包三台机器和原生玻璃回收的配方及真实投料／产物／模组／电源槽，Forge 自行提供终端的同类接口。[自动化物流](../automated-logistics/README.md)已接入，生产前补给真实物品，生产后按消耗回执结算并读取原生库存取出产物；同机嵌套不重复记账，仍按每批结算。

## 义体与设备

- 六件义体按实际持有的正数量物品生效，同类重复不叠加。动能回收、外骨骼和辅助器分别增加机器效率／性能／质量 50%；出售后重新读取时移除，原生模组重新聚合时保留一份加成。睡眠压缩模块每晚增加一次行动。
- AI 核心对非伪人 NPC 交易增加 10 个售价百分点；伪人购买可出售义体增加 25 个百分点，并在预算初始化时将其实际预算加倍。交易仍走原生支付，临时售价特征仅用于 NPC 柜台交易，不计入生产原料价值。
- 高科技眼镜保留独立电源槽，不可出售。等离子燃料、机械手、肉汉堡按原生鉴定价值收费 15 电；红烟、粮票、免疫宁和荧光莓按真实状态收费 5 电。不执行会改变物品的鉴定动作，同一物品状态重复查看不再扣电；切换周目或加载后清空会话缓存。数值以当前游戏为准，包括免疫宁 160／80／40／8 的四种真实基价。
- 机器猫直接摆在展示区时增加 500 吸引力，同类不叠加。义体保管箱仅接收义体，并沿用原生所有权和容器限制、隐藏标签与 `smuggler_bay` 库存身份。
- 拾荒机器人由机械核心、一个有效扫描仪及一个空存储区制造，继承扫描概率和真实货舱掩码。每晚耗电 25，按存档槽／周目／日期去重，10% 概率损坏；一次普通电子元件升级增加 5 扫描概率与 15 基价，最高 100%，一个金属锭修复。只使用自己货舱里的工具，可切换是否收集垃圾；空间不足的未入库战利品会清理。
- 机器人使用原生拾荒次数，计算次数时不受退行性骨关节炎影响，其他原生限制保留。物理电源扣款失败会尝试恢复并核对；无法确认的扣款停止该电源后续尝试，不发放战利品。原生电流转换器和超科技电池保留各自计费／输出语义。
- 便携采矿钻可由玩家或机器人携带，同次拾荒只取最高等级的一把：初始 10%，用一份完美纯度钛合金升级一次至 20%，实际材料价值计入工具；额外矿物权重为金属 50／钛 25／石英 25。适配玩家和机器人共用的原生拾荒重载，避免重复抽取。

## 查询与跨包目录

默认 **G** 打开共享配方查询：指向物品显示其原料／产物用途，指向机器显示加工目录，无目标浏览全部已登记配方。同种目标、窗口或空白再次按键关闭，指向另一种物品再次按键切换。搜索、分页、官方按键选项及打字／拖拽抑制均已接入；同一共享库只维护一个响应实例。K02 动态升级和其他启用提供者的配方自动参与，查询不改变生产规则。

义体目录读取真实工厂的名称、效果、图标和违禁级别。合成扩展自身有六件；启用机械飞升后自动增加其七件义体和一件脑机接口，共十四项。未启用的提供者只显示依赖提示，不注册占位物品或复制其效果逻辑。材料、义体保留原生模板用途类别，义体额外加入原生可显示／筛选的 `CYBERNETIC` 类型。

官方本地化资源包含本包 25 件定义的完整名称、说明和风味文字，共 75 个键，以中英两套文字覆盖 `en` 与各 `zh` locale 标识；终端的资源由 Forge 持有。提示在当前语言读取，机器说明保留配置数值。物流供电通过真实电源权威查询／整笔扣款接入生产、机器人和眼镜；拒绝不再回退原生重复扣款，异常设备源会被本会话隔离。

Demo 存档、旧机器库存图、旧资源路径和移除提供者后的恢复未做正式版转换或验收。保持 ID 不代表 Demo 存档可以直接互通。

## 配置与工程

资源就绪后通过官方 Mod 数据文件 API 创建 `recipes.json`。完整 **schema 26** 目录含 26 条原机器配方和迁入 K01 的 4 条玻璃配方。支持 schema 26 以及手动放入官方数据目录的旧 schema 22–25 文本。按旧规则拆出合并目录、补炼锭路线和 M10，将已知旧终端目标映射到稳定 ID，并将四条玻璃配方从熔炉迁到 K01；保留原配方 ID、K01／K02／K03／K05 加价和有效自定义材料／产量。完整性、重复配方及原身份继续严格校验；只做内存转换，不自动发现或改写 Demo 配置、存档。

配方 ID、Code、机器 ID、输入列表、数量、纯度、机器人特殊材料、可用产物和循环依赖经过校验。无效文件会保留并记录警告，本次运行使用内置配方。修改后重启游戏。

工程使用 `netstandard2.1`，直接引用正式版 Managed 程序集，无 MelonLoader、Il2CppInterop 或其他 Mod DLL 的静态依赖。合包 manifest 只声明入口 `MechcoreProtocol.dll`，通过轻量客户端接入独立的 NicoKobo Forge 前置。配置读写走官方 API，`Capabilities` 为空。供货使用官方顾客生成事件，不再扫描编译器生成的对话方法。
