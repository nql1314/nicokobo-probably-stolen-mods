# 食品加工 / Food Processing

## 当前源码与发布边界

当前源码版本 **2.2.3**，提供 **两台机器、67 条配方、50 种自定义食品饮料和 5 种自定义医疗用品**。可加工原版汽水、能量饮料和泥炭合成肉，并用金属锭扩大机器仓格。

[Steam 创意工坊](https://steamcommunity.com/sharedfiles/filedetails/?id=3831046995)沿用原条目。各版本变更见 [change.log](change.log)。

本机接口核对基线：**Steam Build 26525552**，以安装目录的 Assembly-CSharp.dll 和同 Build 解包代码为依据。既有原生报告仅适用于当时构建，不作为本轮游戏内验收。

## 使用与星级

需要同时启用 **NicoKobo Forge**，使用游戏内置 ModLoader。新周目获得手册，也可在杰克逊夜间商店购买。机器从原版初始模组舱开始，可按原版方式升级。

1. 接通电源、放入合格原料；带水配方还需要满足用水量和水质。
2. 打开配方选择，使用自动模式或指定配方。质量不足的配方仍显示，但不可选择。
3. 过夜加工。指定配方在质量下降、缺料、缺电或输出放不下时暂停，不自动换方。

将一块金属锭拖到自己拥有的机器本体上，材料区和出货区各加一行。每台机器可升四级，两个仓格均从 9×6 扩到 9×10，等级随机器保存。

| 星级 | 机器质量 | 加工加价 | 配方数 |
| --- | ---: | ---: | ---: |
| ★ | ≥0 | 25% | 29 |
| ★★ | ≥50 | 50% | 22 |
| ★★★ | ≥100 | 100% | 16 |

质量只解锁配方，不提高低星配方加价。性能每满 100 点多加工一批，效率影响实际耗电。固定配方最多三种原料。一、二星的固定配方最多两种非水原料。同种多份算一种，代乳、汽水和酒不算水。

## 手册、筛选与输出预览

手册分食品加工器、液体灌装器、医疗／耗材三个页签，以产物图标展示配方。默认按加价排序，也可按加工优先级排列。支持星级筛选，以及产物、原料、类别、品牌关键词搜索；多个关键词用空格分隔。悬停配方可查看用参考原料估算的单件和整批价值。实际加工按投入的原料计价，成交价还会受游戏内交易修正影响。

机器配方窗口可按加工优先级、可制作优先、星级、加价或名称排序。图标亮起表示机器质量合格，已装原料和可用库存能凑齐一批所需原料和水；正式生产仍检查电量和输出空间。选定配方后可点“一键补齐”，从可用库存补入一批缺少的原料和符合要求的水，供料或容器不够时可能只补入一部分。搭配自动化物流时，也可以按指定配方持续补料。

自动顺序：酒品、真伪或浆果条件更多 → 原料种类更多 → 件数更多 → 用水量更多 → 通用分类原料更少 → 配置定义顺序。尺寸条件只决定原料能否投入。跳过质量不足或无法完成的配方，每批采用首个能完成的配方。内置配方之后再尝试扩展配方。界面排序和筛选不改变这个顺序。

只有小块生肉时，自动优先制动物脂肪；加入啤酒且质量达到 50 时，可优先制啤酒炖肉。想做大肉干可以手动指定。

输出框显示按性能、累计原料、水与电量计算的半透明产物和合计数量。自动模式可逐批切换产物；指定配方缺料时保留数量为 0 的预览，质量锁定时不显示可生产产物。预览不创建 GameItem、不占库存、不写入存档。信息按钮展示批数、投料、热量、用水和耗电。

预览不模拟输出空间分配、模块损耗／随机效果，也不调用扩展配方的随机产物选择。真实生产仍检查实际输出空间和每批模块状态。

三种医疗包各有独立的原料池。选定配方后，在食品加工器的原料仓放入对应池子中至少三种不同的单件物品。一键补齐优先补入仓内缺少的种类。每批把仓内属于该池的所有合格单件装进同一个包，重复件也一起装包，其他物品留在原料仓。血袋和止血绷带同时属于普通池和高级池，指定配方可选择要打成哪一档。

- **普通池**：韧棉纤维、医用酒精、基础绷带、止血绷带、外用药膏绷带、避孕药、血袋、嗅盐。
- **高级池**：正品免疫宁注射器、南丁格尔软膏、血袋、医疗用品（普通）、奥克莫吸注射器、罗非鱼植皮片、止血绷带。
- **管制池**：咖啡因药片、芬太片、梦尘、梦魇尘、山奈德片、噬菌霉素片、无证噬菌霉素片、赛纳普斯注射器、蓝血。

双击医疗包或奥克莫吸护理包可把原物取回主库存，空间不足时整包保留。管制池内的物品保留各自原有的违禁属性。包的售价包含原件价值，加工加价和电耗计在包上。

## 营养、价格与品牌

实际加工使用实际原料热量，多份分装保留余数；水、电和无热量标签的原料不凭空生成热量。固定商店／战利品参考热量只用于直接生成的商品。单一肉类来源保留物种标记，混合来源不冒充单一物种。

整批加工基价为 `ceil((实际原料基价＋用水基价) × (1＋星级加价)＋基础耗电成本)`，之后分给产物。加工出的原版物品取单件分摊值和原版基础价值中较高的一项。原料计价排除零售、顾客与事件溢价。使用中间成品的下一道配方按该成品实际基价计算，会逐道加价。所有配方均使用对应星级的加价。

血清保留原生十次用途，加工价值按剩余次数递减，转移用途时携带对应价值。鱼饲料保留实际热量、原生拆分／合并与75%生长效率，加工价值随剩余热量递减；没有加工价值标签的原版饲料维持原价。价值读取和耗材操作使用定向 Harmony 补丁，游戏升级后需复核目标方法。

饮料和酒心巧克力的酒精标记来自配方分类，酒精强度按实际消耗酒料的件数加权。咖啡、酒饮和品牌描述不添加新的提神或饮酒动作。

物品名称下方只显示公司名称，不显示品牌徽标。新增24种产品使用独立绘制的原版风格像素图标；啤酒炖肉替换旧肉串图，保持原有占格。25张原图和完整提示词保存在 `Assets/IconSources/food-v1.4/`，使用内置 image_gen 逐张绘制。运行 `python tools/assets/export-food-icons.py` 可沿用现有透明边界和最近邻导出流程，生成 `Textures/Items/` 的16像素网格图标。

F42–F53 的 12 张图标原图和提示词保存在 `Assets/IconSources/food-v2.1/`，沿用同一导出流程。

芝士拌面、肉酱拌面、鱼松拌面及奥克莫吸护理包使用重绘图标，果味鱼肉冷餐和夜班果冻以原设计重画为正向图。图集、提示词和切图坐标见 [food-v2.2-front-view](Assets/IconSources/food-v2.2-front-view/prompts.json)。

三种医疗包参考护理包绘制正向图标。原图与生成提示词见 [医疗包图标](Assets/IconSources/food-medical-kits/prompts.json)。

咖啡啤酒和码头气泡啤各占 1×2，莓果泉水汽泡占 1×3。三款饮料沿用原瓶身素材，旧存档载入时应用新占格。

本轮新增中文、英文文案；其他语言的新条目暂回退英文。权威本地化源为 `../Localization.csv`，编译通过既有生成流程生成资源，不直接编辑 obj 中的生成文件。

原有冷链：拼盘、鱼肉纤维沙拉可冰镇；繁星圣代、补给果冻、鱼卵纤维饼可冷冻。新增饮品沿用原生饮料冰镇。冷链改变售价，不增加热量或营养液恢复效果。

## 配置与旧存档

当前 `recipes.json` 为 **schema 10**。可调整原料数量、产量以及收紧允许的原料条件；不能更改身份、配方星级或放宽必要准入条件。护理包固定一包对应各一件原料。`MarkupPercent` 必须与星级对应；机器 `ProductionMarkups` 仅保留给扩展配方使用。

读取 schema 8 或 9 时，保留已有设置并在内存中补齐新增配方。读取 schema 7 时，保留产量和仍适用的原料数量，更新原料组合与星级加价并补齐当前配方。迁移不覆盖用户文件。无效配置保留并记录原因，本次运行使用内置默认。

已有物品与配方 ID 保留。“啤酒炖肉”仍使用旧 `spicy_meat_bites` ID；旧机器的电池、模块、输入、输出、便签、水槽存档下标不变。食品热量、加工价值和所选配方通过正常物品标签保存；旧商品不会凭空补算历史加工成本。
