为机器补回实际消耗的原料，收取成品，并通过虚空仓储、水罐、共享电网和网络终端管理库存与生产。

需要单独安装并启用 [NicoKobo Forge](../nicokobo-forge/README.md)。合成扩展、食品加工为可选搭配；未安装时仍可使用支持的原生机器，物流模组在 Forge 的全域制造终端制造。

## 快速使用

1. 启用 Forge 和本 Mod 后重启游戏。每周目可获得一个网络终端；主仓库没有空位时等待领取。
2. 制造补货模组、弹出模组，装入支持的机器。每类一个即可，重复安装不加速，补货与收取分别启停。
3. 手动加入第一批原料、真实电池和所需水容器。备用材料依次从资源网络、同区域四周容器、主仓库取用，成品按同样顺序送出；液体只倒出内容，容器保留。
4. 持有终端按 **H** 打开管理窗口。快捷键及 Ctrl、Alt、Shift 组合可在 Mod 设置中修改。水培需先在机器详情点击“记录补液规格”，换桶或手动改液后重新记录。

## 设备、制造与扩容

| 物品 | 获得方式 | 容量或用途 |
| --- | --- | --- |
| 补货模组 | 普通电子元件×1＋金属锭×1，每批 2 个 | 按实际消耗及材料规格补货 |
| 弹出模组 | 普通电子元件×1＋线缆×2，每批 2 个 | 收取原生成品，与补货独立启停 |
| 网络终端 | 每周目一次的待领取奖励 | H 打开库存、统计和机器物流 |
| 虚空容器 | 展示柜扩建 1 后免费 1 个，随后可制造 | 初始 1 页，每页 20×5，单页最多 20×20，最多 5 页 |
| 虚空水罐 | 铁锈水直供后免费 1 个，随后可制造 | 初始 10 L，最多 1000 L |
| 虚空电网 | 简易反应堆开局免费 1 个，其他周目完成商用级供电单元后免费 1 个。解锁后可制造 | 初始 16×5 / 5000 kJ，最多 16×16 / 16000 kJ |

两种模组在合成扩展的机电工作台制造；该机器未登记时使用 Forge 全域制造终端。三个虚空设备在全域制造终端制造，分别消耗完美金属锭×1和空存储区、水容器或机器区×1。虚空容器和水罐要求对应人脉升级，虚空电网要求简易反应堆天赋或商用级供电单元升级。模组制造价格按生产机器的实际材料价值、溢价率和基础电费计算，再按本批产量分摊。

虚空设备占 3×3 格，禁止交易。同类设备共享容量升级，各容器与水罐分别存放内容，电网共享储电账本。按住 **Alt** 拖入对应材料扩容：空储物容器按有效格数折算行数，空水容器增加其容量，高纯度及以上金属锭每块增加电网一行和 1000 kJ。带内容的容器和超过上限的材料不会被消耗。

对虚空容器使用原版存储区扩建套件，每个套件增加 1 个标签页，最多 5 页；达到上限后不再消耗套件。标签页只扩建当前这个容器，新增页沿用当前单页容量；Alt 空容器扩容仍共享到所有虚空容器的全部标签页。双击当前标签可使用原生重命名，各页内容、名称和页数随物品存档恢复。

虚空容器的所有标签页均接入资源网络和库存统计，不接收机器、容器或水容器。先放入一个物品样本，再在对应页的空白处右键，可归集同类物品到该页；锁定、使用中和机器内部的物品不会被取走，放不下的物品保留原位。整理沿用游戏原生功能。

水罐支持双向倒水，保留实际组分、水质和逐组分价值，支持六级原生水；已有水的接收桶只自动接收同级水。也可拖到养殖系统固定水箱补水，或拖到排水口倒空。图标随水位和水质变化。

## 机器自动化范围

| 机器 | 自动化行为 |
| --- | --- |
| 熔炉 | 补回实际消耗的材料，收取原生炼制产物 |
| 净水器 | 默认达到当前机器纯度上限后收水，也可切换为纯水目标；按实际收水量补回已记录的原水 |
| 水分收集器 | 收取已生成的液体，保留输出桶；无需补料 |
| 密码解序器 | 补实际耗料、收产物，保留目标芯片 |
| 3D 打印机 | 支持普通、金属／CNC 和近战批量；补启动时实际消耗的原料，等最终品质处理后收取成品 |
| 蒸发器 | 只收原生蒸馏液；原液桶、蒸馏桶和浓缩残液保留，原液手动投放 |
| 水培 | 按记录的真实液体规格补给，收取作物与返种，保留基因和营养状态；播种与换种由玩家操作 |
| DNA 操纵器 | 只收原生弹出槽中的磁盘，保留磁盘状态；不操作种子、工作盘或基因应用／提取 |
| 自动喂食器 | 只补手动指定过的粮食；开启原生自动混粮后按剩余容量逐份补入，满仓等待消耗 |

安装对应内容包后，还支持材料精炼机、食品加工器、机电工作台、精密装配机、液体灌装器和全域制造终端。

净水目标不可达或剩余组分无法净化时，终端显示原因，原桶保留。打印的芯片、模组、电池、进度和品质由原生处理；换芯片或模组组合后停止执行不适用的补料需求。蒸发器没有蒸馏桶时原生仍可能继续蒸发。水培的正常生长可改变余液浓度，补液不会自动调配到某个营养目标，也不会自动播种；DNA 原生开关控制磁盘是否进入弹出槽，物流只控制入槽后的搬运。

自动化只补料和搬运，不额外启动机器或增加生产机会。夜间顺序为原生机器、材料精炼／食品加工、机电工作台、精密装配、液体灌装、全域制造终端，每机保留其原有批次数。下游收不下时，未转移的物品保留原位；水培输出满会按原生规则转入主库存，打印满输出的实际去向尚待游戏内验收。酒架沿用原生取酒方式。

## 共享供电

在虚空电网中放入电池或充能设备。储电电池按原生 ENERGY_CELL 类别和电量标签识别，不再限定物品 ID；一次性电池可存电，但不能用电网充电。电网只记录电池实际交出的电量；容量不足时余电留在电池，每天充电后再次收电，取出空电池不会减少已储电量。养殖系统不能放入电网或其中的充能设备。

支持的设备仍需安装真实本地电池，接网不要求额外安装物流模组。用电前，本地电量严格高于 **25%** 且足够时整笔用本地；否则优先整笔用电网，电网不足时再用足够的本地电池。两边余额不合并，单次耗电不超过原电池容量。拖动电网到电池或设备可将其充满，电量不足以充满时双方保持原值。

超科技能量单元可放入虚空电网，每晚结束时按当前输出量发电；默认每个每晚 12 kJ，每次原生输出升级增加 10 kJ。各单元每天只结算一次，记录随周目保存；电网满时溢出电量不保留。同一单元放在机器内时仍按原生单次输出限制直供，不接网充值或拼接支付。

普通区域中的养殖系统保留原生电鳗发电，并按外沿四周有效格数增加电网输出；电池、充能设备和能量阵列的实际占格会被排除。同机同日发电收据随周目保存，重载不重复发电，溢出电量不保留。

## 终端与保存

H 终端提供库存搜索、类型／标签筛选、名称／价值排序和原生物品详情，以及电量、三个可用水级最近 10 个结算日的净变化。机器详情分别显示最近补货结果、收取结果、供电与等待原因，支持设置净水目标、记录水培补液规格和打开原生机器窗口。绿灯表示物流开启，机器加工仍需满足原生条件。设备可通过原生右键菜单命名。

取放操作使用实体库存，周目状态随游戏正常保存；内存更新不代表已经存盘。网络终端与免费设备每周目各领取一次，满仓等待空位，领取后卖掉或销毁不会重新赠送。同版本保存与读档保留机器设置、补液规格、待补数量、网络内容和去重记录。

## 开发与验证

本包仅交付 `Nicokobo.AutomatedLogistics.dll` 和自身资源，通过独立 Forge 前置提供内容接口，协议版本 1，不附带公共 ContentInterop DLL。`Capabilities` 为空。库存枚举使用公开 `PlayerStore.FindAllItem`，物品移动使用原生 `GameInventory`／`SlotMarker`，不读取私有 `saveBags`，不补丁原生排序比较器；UI 与设备使用限定到明确游戏类型的调用。

周目状态格式为 schema 6，键为 `nicokobo.automated_logistics.runtime_v6`，与对外发布版本号分别管理。保存机器 UID、开关、净水目标、补液样本与容器身份、待补量、网络内容和当前局收据，不提供开发草案的旧格式迁移。

同一 schema 中已有的香水待补数量继续保留；先前未记录次数的补货记录只接受满次数香水，新记录按真实消耗次数和上限匹配。

## English

Automated Logistics uses the full release's built-in ModLoader and requires NicoKobo Forge. Restock consumed materials, collect finished products and manage real inventories, liquids and shared power through the H-key terminal. Supports native machines and optional Synthesis Expansion / Food Processing integrations. Printers retain their chips, progress and final quality; evaporators collect distillate only; hydroponic feed uses a recorded specification without automatic planting; DNA collection is limited to the native eject slot. Local batteries, physical capacity and Hypertech output limits remain in effect. For full player instructions, see [the Workshop description](workshop-description.txt).
