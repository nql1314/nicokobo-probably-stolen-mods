# 自动化物流：设计文档

更新：2026-10-30。当前正式版源码／manifest **1.0.0**，Mod ID `nicokobo.automated_logistics`，入口 `Nicokobo.AutomatedLogistics.dll`。需要正式版 Forge 协议 1；合成扩展和食品加工为可选搭配。游戏依据为 0.46D / Build 26284217，共用规则见[总览](README.md)。

## 定位与核心循环

玩家通过首次投料和设备设置确定生产意图，物流补回实际消耗、转移真实产物，再用资源网络、水罐、电网与 H 终端集中管理。机器是否工作、工作次数、品质、芯片和基因仍由原生或提供者决定。

制造设备 → 放置首批原料、电池与水容器 → 安装补货／弹出模组 → 选择机器设置或记录水培补液规格 → 正常加工 → 查看等待原因、补充来源及扩容。

保存键已在运行层与原生适配中统一为 `runtime_v6`，由 Forge 公共暂存接口检查当前 store、周目、槽位和旧值；完整网络与跨进程保存仍待原生验收。

## 六种设备与取得方式

| 设备 | 取得与制造 | 初始能力 |
| --- | --- | --- |
| 补货模组 | 普通电子元件 ×1＋金属锭 ×1 → 模组 ×2 | 按实际消耗及材料状态补回 |
| 弹出模组 | 普通电子元件 ×1＋线缆 ×2 → 模组 ×2 | 收取实际产物，与补货独立启停 |
| 网络终端 | 每周目一次待领取奖励 | 实际持有后按 H 打开终端 |
| 虚空容器 | 展示柜扩建 I 后免费一件，也可制造 | 20×5，最多 20×20 |
| 虚空水罐 | 铁锈水直供后免费一件，也可制造 | 10 L，最多 1000 L |
| 虚空电网 | 简易反应堆开局免费一件，其他周目完成商用级供电单元后免费一件。两种途径均可开放制造 | 16×5、5000 kJ，最多 16×16、16000 kJ |

两种模组优先在合成扩展机电工作台制造，机器未登记时使用 Forge 全域制造终端。三个虚空设备在全域终端制造，分别用完美金属锭 ×1及空存储区、水容器或机器区 ×1，要求对应人脉升级。

模组制造价由实际材料、所用机器加价和基础电费计算，再按批量分摊；不是固定免费复制。三个虚空设备占 3×3、禁止交易。同类容量升级共享，各容器／水罐仍各自存物，电网使用共享储电账本。

免费设备与终端均按周目保存领取收据，满仓等待空位；领取后出售或销毁不重新赠送。

虚空容器、水罐和电网的首个设备丢失后，由本周目仍持有的同类设备接替；原设备有效时保持原绑定，失效时按实例 ID 选择替代物并保存新绑定。没有同类设备时网络离线，之后获得同类设备可恢复。接替保留领取收据、共享容量和储电账本，各实体的物品与液体仍留在原处。

## 补货、弹出与来源

补货欠额只来自合法加工中观察到的真实消耗；手动取走原料不扩大欠额，后续手动补回可以抵扣。固体保留纯度、品级及加工相关状态，液体保留组分、水质和价值基准，不把相同 ID 的任意物品当作等价原料。

同步神经活性香水还记录真实使用次数及上限；消耗满瓶后，部分使用的同名香水不能抵扣补货欠额。同一 schema 6 中此前未记录次数的香水欠额保留原数量、纯度和品级，只接受启用使用次数标签、上限大于零且当前次数等于上限的满瓶；不推断过去的具体次数上限。已有非空次数规格继续严格匹配。

物品来源及产物去向均依次为：**资源网络 → 同区域四周容器 → 主仓库**。每层只处理可转移的实际余量，前层不能接收就继续下一层，最终放不下的部分留原位。容器外壳、机器及嵌套库存由玩家按真实配方手动准备，不自动吞掉带内容的容器。

补货模组与弹出模组分别控制启停，每类一个即可，重复安装不提速。机器、电池、芯片、模组及工作盘等按实际槽位身份排除，不能仅因位于机器库存就全部弹出。锁定、使用中、祖先容器限制、所有权及原生放置规则继续有效。

每批加工单独观察。失败回调不生成成功消耗，不借回调次数扩充生产。夜间只结算已经产生的真实机会，按既有依赖顺序衔接生产，先于矩阵闲置衰退完成。

## 原生机器适配

| 机器 | 补货／收取范围 | 由玩家或原生继续负责 |
| --- | --- | --- |
| 熔炉 | 按实际批次补耗料、收炼制产物，兼容既有玻璃回收 | 原生配比、废品、高炉、品质及加工机会 |
| 净水器 | 达到选定目标后倒出水，按实际收取量补回记录的原水 | 净化上限与去污规则、真实接收桶 |
| 水分收集器 | 收实际生成液体，保留输出容器，不补原料 | 原生集水和工作 |
| 密码解序器 | 补实际耗料、收真实目标物 | 目标芯片保留，解码与缓存沿原生路径 |
| 3D 打印机 | 普通、金属／CNC、近战批量；补启动消耗，最终品质处理后收成品 | 芯片、模式、进度、性能、品质与原生最终产物 |
| 蒸发器 | 只收原生蒸馏液 | 原液手投；原液桶、蒸馏桶和浓缩残液保留 |
| 水培 | 按记录规格补液，收作物与返种，保留基因／营养状态 | 播种、换种、配制目标营养液和原生生长 |
| DNA 操纵器 | 只收原生弹出槽中的完整磁盘 | 种子、工作盘、基因提取／应用、稳定性和耗次 |

安装提供者后，还支持合成扩展的精炼机、机电工作台、精密装配机、全域制造终端，以及食品加工的食品加工器、液体灌装器。配方和实际库存端口从提供者读取，不在物流复制一套生产定义。

### 净水目标

默认选择当前机器纯度上限，可切换为纯水。持续净化不记为原水消耗，只有自动收水的体积形成原水欠额；余下成品未收完前不混入原水。目标不可达、剩余组分不能处理或接收水级不符时，原桶留位并显示原因。

原版只有实际去污才扣电、触发有效工作。矩阵 S24 的附加净化上限仍有独立待办，组合效果须在其方案落地后复核，不能由物流界面承诺已经一致。

### 打印、水培和蒸发

打印的物品消费发生在真实启动点，收取必须等待最终品质；更换芯片或模组组合后停止执行旧规格欠额。输出满时实际原生产物去向仍待游戏内验收。

水培先由玩家在详情页“记录补液规格”；正常生长改变余液浓度不要求重新记录。换桶或手动改变液体后重录；补液只匹配所记录的真实规格，不自动纠正至某个营养目标，也不播种。输出满时作物按原生规则转入主库存。

蒸发器没有蒸馏桶时原生仍可能继续蒸发，物流不把自动收取描述为停机保护。DNA 的原生开关决定磁盘是否进入弹出槽，物流只搬运已经进入该槽的物品。

## 虚空仓储与水罐

按住 Alt 拖入合格材料扩容：空储物容器按真实有效格数折算资源行数，空水容器增加容量，高纯度及以上金属锭每块增加电网一行及 1000 kJ。材料带内容、无效或超过上限时不消耗。

虚空容器不接收机器、容器和水容器。先放一个样本，再在内部空白处右键可归集同类物品；使用中、锁定、机器内部的物品不取，放不下则保留原位，整理沿原生功能。

水罐双向倒液，保留真实组分、水质及逐组分价值，支持六级原生水。已有水的接收桶只自动接受同级水；可拖至养殖固定水箱补水或排水口倒空。水量、水质与图标同步，容器壳不随内容搬运。

## 共享电网

电网存放真实电池或充能设备，只记实际交出的电量，充不满容量时余电留电池；每日充电后可再收电，取空电池不会删除已经储入的电量。

支持的机器仍须安装本地真实电池，不要求额外物流模组。整笔电费的选择为：

1. 本地电量严格高于容量 25% 且足够，整笔用本地。
2. 否则电网足够，整笔用电网。
3. 电网不足而本地仍够，整笔用本地；两者都不足则失败。

两边不合并支付，单笔不能超过原电池容量。拖动电网到电池／设备可充满，不能充满则双方不动。Hypertech 电池保留单次输出限制，不存入电网、不接网充值、不拼接余额。已识别电源拒绝扣费后不回退重复扣款。

普通区域的养殖系统保留原生电鳗发电，并按外沿四周有效格数增加电网输出，排除电池、充能设备及能量阵列真实占格；养殖系统不能塞入电网。发电按机器／日期去重并随周目保存，溢出不保留。

## H 终端与反馈

实际持有网络终端后按 H，可在设置修改按键与 Ctrl／Alt／Shift。终端提供库存搜索、类型／标签筛选、名称／价值排序、原生物品详情，以及电量和三个可用水级最近 10 个结算日净变化。

机器详情分别显示最近补货结果、收取结果、供电、暂停原因，支持净水目标、水培规格和打开原生机器窗口。绿灯只表示物流开启，不承诺机器已经满足加工条件。设备名称通过原生右键菜单维护。

## 保存与当前验证边界

当前使用 **schema 6** 和周目键 `nicokobo.automated_logistics.runtime_v6`。机器 UID、开关、净水目标、水培样本及容器身份、待补量、网络内容、命名、统计和领取／发电收据仍由物流持有，不增加旧格式转换。

运行层、[NativeRunData.cs](../../mods/automated-logistics/Native/NativeRunData.cs) 与原生保存钩子均使用同一个 `SaveKey`；内容适配调用 Forge 的 `RunDataGate`，校验当前 PlayerStore、周目、槽位和旧 JSON 后暂存。内存暂存不代表文件已保存，实际提交仍由原版保存流程负责。正常保存、网络实物与跨进程重载继续独立验收。
