# 食品加工——料理与饮品设计文档

更新：2026-11-05。当前源码包含未发布改动，manifest **1.0.1**，Mod ID `nicokobo.food_processing`，入口 `Nicokobo.FoodProcessing.dll`。需要正式版 Forge 协议 1，游戏依据为 0.46D / Build 26337366。共用规则见[总览](README.md)。

## 定位与玩家循环

把鱼肉、菌菇、水培作物和普通食品接入有取舍的料理、饮品与养殖补给生产。不同路线分别提供食材利用、空间压缩、高档商品、修补身体材料或原生畜牧用品，不靠大量同质菜名扩张目录。

取得手册和设备 → 准备真实原料、水与电 → 自动或指定配方 → 过夜加工 → 冷链、出售、食用或投入下游。可选物流负责按所选配方补回实物，不替玩家改生产目标。

当前为 **19 件定义：2 台机器、1 本手册、16 种自定义食品饮料**；另有原生动物脂肪、速食拉面、奶酪、工业鱼饲料、两种血清、外用酒精与蓝血袋产物。固定目录共 **25 条配方**，K04 12条、K06 13条；机械飞升追加修补胶不计入这25条。

## 原料准入与真实营养

按真实物品检查可食分类、污染、染朊和腐败，不检查额外化学组分，之后才计算批次。污染鱼肉／鱼卵不能因保留相同 ID 就变成干净食品；有足够合格物品时可跨堆选料，否则整批暂停。配方查询在原料前显示“污染、染朊或腐败的原料无法加工”，机器配方页、手册和提示采用相同说明。

鱼片接受极小、小、标准及大鱼片的明确 ID，每件读取实际营养与价值，不统一折成标准份；鳗鱼片接受小／标准尺寸。食用帽菇、小块肉和酒基只使用有限原料组。食用梦菇按真实可食分类和违禁状态判断，不把所有同类物品泛化为可替代原料。

原料覆盖 **35 个原生食品 ID／明确食用变体**，另有普通酵母及既有医疗、化学材料。种子和不明食物不因名称相似而入池；奶酪新路线仅使用普通酵母，不接受非法替代酵母。原料组与条件见 [FoodIngredients.cs](../../mods/food-processing/FoodIngredients.cs)。

热量按实际消耗份额相加，多份成品保存总量与余数；水、电、普通非食品标签不生成营养。允许跨物种混肉，单一物种保留来源，混合批次不标记为某一种物种；鱼子酱的产卵鱼来源不作为肉料来源。F32 气泡酒接受红啤酒、努特加和已发酵完成且可饮用的正品自酿酒，空瓶、发酵中酒、失败酒和假酒不可投入。读取实际酒基强度，按本批消耗件数计算 `sum(ALCOHOL_VALUE × 消耗件数) / sum(消耗件数)`；沿用整数精度，除法截断，未消耗的堆叠余量不参与。酒基数量仍可配置，默认单件结果不变。咖啡和气泡酒没有新增提神或额外饮用动作。

原生奶酪保留实际热量与制造基准，可继续用于料理和捕鼠笼。工业鱼饲料根据实际热量生成，沿用每 50 kcal 价值 1、原生拆合及 75% 生长效率，不能用食品加价或固定供货热量复制价值。两种血清使用原生十次用途和剩余次数计价。

## 生产、选择与失败结果

机器默认按原料种类数、件数及用水量的优先级自动选择；相同投料规模时，明确物品配方优先于标签类别配方。小块生肉×2自动优先制作脂肪，标准生肉×2仍制作大肉干；指定大肉干时仍可使用小块生肉。也可通过配方按钮指定固定或可用跨包配方。指定模式缺料就暂停，不偷偷转产其他菜；保存选择的稳定配方 ID，提供者缺失则显示不可用。

每批确认真实原料、水质、电源和完整产物放置后提交；缺料、缺水、缺电或满输出时不消耗，不记成功，也不触发有效工作成长。发生部分变动时由实际事务补偿。成功提交后才通知物流，失败回调不能增加补货欠额。

G 查询在普通目录中显示原料组与条件，指向机器时追加当前实际投料、热量、水量、电量、指定目标及等待原因。查询、原料槽、物流选料和实际扣料使用同一准入规则。

## 价格与冷链

自定义普通成品生产基准按整批计算：`B = ceil(实际原料及用水价值 × (1＋配方加价)＋机器基础电力价值)`，再按份数分配，整批只取整一次。现有用水计价以 25 ml 为一个未修饰价值单位；这不是额外实际付款。

保留原料自身纯度、品相和加工价值，排除顾客、零售及事件临时溢价。效率改变实际扣电，不反向改写已确定的基础电力价值，也不生成热量。供货固定参考价不能代替每批的真实投入价，不以生产基准高于原料基价证明买料加工一定盈利。

| 冷链 | 支持的自定义成品 |
| --- | --- |
| 原生冰镇 | 鱼子酱鳗鱼拼盘、果味鱼肉冷餐；果汁、咖啡、营养液、气泡酒沿用饮料冰镇 |
| 原生冷冻 | 繁星圣代、复合补给冻、鱼卵蔬纤饼 |

冷链沿用原生冰箱电耗和售价特征，只改变商品售价，不额外增加热量、养殖营养或伪人营养液恢复。饮料不新增冷冻资格，原生奶酪及耗材继续各自的原生适用规则。

## 跨包联动

- **机械飞升**：K04 允许追加血袋／植皮两种修补胶；压缩营养液按该件生产基准恢复健康，冷链售价不再抬高恢复。
- **自动化物流**：补货目标服从所选配方，传递真实消耗与水量；当前物流保存接线问题见[物流设计](AUTOMATED_LOGISTICS.md)，不能以食品单包成功推定整条物流已验收。
- **模组矩阵及合成义体**：机器仍走标准属性及真实有效工作接口，不复制连续成长、增压器或机器加成逻辑。
- **共享供货与 G 查询**：共用一次预算及一个窗口，按实际提供者显示；临时 NPC 加价不进入生产成本。

## 配置、保存与资源

官方数据目录 `recipes.json` 当前为 **schema 7**，支持件数、产量、合法条件及 `MarkupPercent`。显式配方加价优先于机器默认，饲料始终用原生热量计价；配置不能绕过原料身份、污染或真实用途校验。无效文件保留并记录原因，本次运行使用内置默认，修改后重启。

读取旧schema 7文件时，允许缺少新增F36／F37／F38，在内存中补入默认值；原有22条配方和机器加价保持配置值，文件不被覆盖。其他配方缺失仍按无效配置处理。

热量、生产基准及机器配方选择随正常原生保存；饲料用原生保存与拆合。不保留已删除的重复成品工厂或开发旧配置导入，不新增 Demo 迁移。

中英两套源文字覆盖 en 及各 zh locale。本地化 CSV 由 `ContentText` 与定义生成，应改源文字再运行现有生成入口，不直接把生成结果当作设计源。图标提示词保留在源码资源目录。
