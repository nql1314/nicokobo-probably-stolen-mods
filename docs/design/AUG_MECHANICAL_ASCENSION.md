# 伪人：机械飞升——设计文档

更新：2026-10-31。当前是[机核协议 / Mechcore Protocol](../../mods/mechcore-protocol/README.md) **1.0.0** 的内部组件；包 ID `nicokobo.mechcore_protocol`，唯一程序集 `MechcoreProtocol.dll`。组件内容与数据 owner `nicokobo.aug` 保留。外部前置仅 Forge（协议 1、固定能力 API 1），食品加工为可选联动；合成、矩阵与机械飞升已同包提供。编译基线为 0.46D / Build 26337366，合包尚未原生验收。共用规则见[总览](README.md)。

## 定位与核心循环

玩家是一枚在改造身体中醒来的 AI，继承当铺、旧伤和未结清的生意。经营提供维持身体及隐藏身份的资金，工业制造提供义体，工坊把实际持有的成果组织成飞升目标；旧收据、照片和录音逐步揭示原主与 LF-041 批次的遭遇。

经营与采购 → 修补健康、降低暴露 → 制造并持有义体 → 完成工坊证明 → 推进调查与人物交易 → 完成机械飞升并选择终局处置。生存、持有效果、工坊成就和剧情选择各自记录，不能把完成成就等同于永久持有全部义体。

## 开局与生存

官方独立开局使用原生 MODDED 身份及稳定场景 ID，不占用旧 Demo 的私有数字开局类型，不使用特性点。

| 项目 | 默认规则 |
| --- | --- |
| 经济 | 信用点 500、租金 250、治安部声望 −15 |
| 健康 | 初始／上限 100，每日损失 10 |
| 暴露 | 初始 20、上限 100，每日增长 5，无开局宽限 |
| 开局物资 | 脑机接口、材料精炼机、满电能量电池、普通电子元件、外用药膏绷带、废金属 10（其中 9 在精炼机内）、材料霓虹灯牌 |
| 电子吸收 | 每件普通电子元件降低暴露 25，独立于身体修补 |
| 失败 | 健康耗尽或暴露达到上限时按本 Mod 失败规则结算 |
| 飞升后 | 免除本 Mod 每日健康损耗及自然暴露增长，不因此免除所有原生经营风险 |

低暴露对非同类顾客的基础售价惩罚为 10%；暴露达到 35／75 时为 25%／50%。同类交易加成及合成扩展 AI 核心的补偿分别由实际效果处理。合成声带提高触发阈值，不直接降低暴露。

每日损耗、暴露变化和义体修正显示在 HUD／状态页；按本周目配置快照结算，同一日不重复扣除。数值依据为 [AugNumbers.cs](../../mods/aug-mechanical-ascension/AugNumbers.cs) 与 [SurvivalRules.cs](../../mods/aug-mechanical-ascension/Domain/SurvivalRules.cs)。

## 身体修补与自产耗材

“修补身体”使用明确白名单，恢复量取该件内在价值或已保存生产基准与当前健康缺口的较小值。超额不储存，健康已满不消耗。它只恢复伪人健康；原生使用、治伤、疾病和药物效果保持各自入口，一件物品不能重复取得两套效果。

| 合格材料 | 无额外品相修饰的参考恢复量 |
| --- | --- |
| 普通医疗材料 `common_medical` | 40 |
| 普通绷带 `bandage_item` | 8 |
| 止血绷带／外用药膏绷带 | 各 16 |
| 药膏 `salve` | 80 |
| 血袋 `blood_bag` | 33 |
| 蓝血袋 `blue_blood_bag` | 250，仍受健康缺口限制 |
| 罗非鱼植皮片 `tilapia_skin_graft` | 24 |
| 仿生修补胶 | 读取本件生产基准，普通两条路线参考为 62／50 |
| 食品加工的压缩营养液 | 读取本件生产基准，实际批次可变；热量和冷链售价不换算成额外恢复 |

工具、义体、脑机、普通药片、免疫宁、酒精、畜牧血清、医疗鱼卵及未明确接入的第三方物品不进入修补清单。原生 `restricted_medical` 仍是缺少正价值及完整功能的占位定义，不能当作可用的管制医疗补给。

仿生修补胶 ID 为 `nicokobo.aug.bionic_repair_gel`，由机械飞升提供实物；安装可选的食品加工后，向 K04 液体灌装器追加两条配方，每批各产一件。未安装时配方不显示，成品仍可通过医疗掉落和供货获得：

| 路线 | 投入 |
| --- | --- |
| 血袋路线 | 血袋 ×1＋普通绷带 ×1 |
| 植皮路线 | 植皮片 ×1＋普通绷带 ×1 |

两条路线共享成品身份，保存各自实际生产基准；K04、G 查询与实际修补都读取同一件的状态。胶也进入现有医疗掉落及共享供货。压缩营养液虽沿用 `nicokobo.mechcore.synthesis.*` ID，真实提供者是食品加工。

## 脑机接口

脑机 ID `nicokobo.aug.brain_computer_interface_module`，为真实 1×1 物品。当前拥有 N 件时，**每枚**基础性能／效率／质量为 `8N／8N／4N`；拥有量上限 25，不能只统计目标机器里安装的数量。

固定超频取相邻正向基础属性的 25%，不把机器总值或临时加成反馈给自身计算。能力由 Forge 私有表按脑机身份分派，不进入原版随机词缀目录，不使用随机候选表 IL 补丁。

下一枚正常报价以 100 为基数，按非成就奖励形成的持有增长逐次翻倍；成就赠送的脑机数量另记。实际交付、扣款及奖励收据完成后才计数，纸面领取记录不能凭空提供属性。面板显示 N、每枚三属性、当前有效超频来源及下一枚报价。

拟态皮肤当前已不消耗血袋或普通化学用品，香水须为满次数（正常 5/5）；参考工厂价 354 不代表所有制造实例同价。音乐磁带必须有真实音乐内容。脚踝、红外及涡轮的有效范围以真实持有及原生加工入口判断，同类不重复叠加。

合成扩展另外提供六件义体及其睡眠、机器三属性、AI 交易和眼镜能力；机械飞升不重复实现。合成扩展的义体目录在两包可用时列出 13 件义体加脑机，共 14 项。认知涡轮是辅助义体，不增加工坊必交证明数量。

## Nico 工坊与最终飞升

按 **N** 或使用 Nico 名片打开。仅在打开或切换到机械飞升成就页时检查玩家真实拥有的正数量证明物，锁存该物品 UID；关闭、界面刷新、物品变动及保存均不额外扫描成就库存。证明不消耗物品，也不要求亲手制造。前置奖励先领，再领后续节点，十二项全领后开放最终飞升。

| 分支 | 证明顺序 | 对应奖励顺序 |
| --- | --- | --- |
| 视觉 | 红外视觉 → 高科技眼镜 | 拾荒扫描仪 ×1 → 满电二型电池 ×1 |
| 行动 | 人工脚踝 → 睡眠压缩模块 → 全息通讯器 | 等离子切割机 ×1 → 高级涡轮增压器 ×1 → 满电自充电能量电池 ×1 |
| 机器 | 钛合金外骨骼 → 动能回收 → 精细动作辅助器 | 性能转换节点 ×1 → 节能转换节点 ×1 → 质量转换节点 ×1 |
| 身份与生存 | 合成声带 → 拟态皮肤 → AI 核心 → 人工心脏 | 外科手术工具套装 ×1 → 外科手术工具套装 ×1 → 脑机 ×1 → 脑机 ×1 |
| 最终 | 十二项奖励全部领取 → 机械飞升 | 脑机 ×1＋神经核心模组（无限制）×1及本 Mod 生存压力解除 |

未打开本页前已出售或消耗的证明物不补记；记录过证明后出售该件，不撤销已完成证明；其持有效果仍立即按实际产权停止。工坊明确区分缺少实物、提供者不可用、前置未领、可领取和已领取，并提供机器／配方查询入口。整份奖励可完整放入并核对后才提交领取，不因满仓丢奖或重复发放。

## 灰线与工业供给

完成 E02 后灰线在约定周二作为当天最后一位来客，电话查询安排。定位为矿料、设备、模组与工业材料，保持货单、交易、实物和收据绑定；开局纸条另外说明普通配给站和身体修补入口，不新建保底医生。

货单筛选同时检查真实注册工厂和跨包提供者。节点与模组使用当前可取得目录；原生商品按当前真实价值、自定义商品按定义及实例状态报价，最终渠道加价 **25%** 只加一次，不用旧目录价格强行托底。付款以实际 `BuyItem` 入口维护一次事务。

灰线不会因所有权 ID 含 `synthesis` 就误认食品提供者，也不把全部医疗品复制进自己的货单。普通医疗追加供货仍共用六包预算。

## 失物招领：主线与选择

主线围绕身体原主、林岑、灰线和公司经手人邵衡展开。LF-041 的有限改造合同、未授权的人格清理、原主切断控制并放出 AI 的行动逐步被证据确认；知情、交付、核心同意和最终处置分别成立，不能从一次好意自动推导全部授权。

| 事件 | 前置与排期 | 关键选择、实物及后果 |
| --- | --- | --- |
| E01 退货 | 伪人周目至少过夜一次 | 付 60 收旧义体与收据，或拒收只得收据；拒收关闭依赖旧义体的隐藏调查 |
| E02 灰线 | E01 后约定周二 | 维修索引、钛合金 ×1，解锁灰线联系及周二供货 |
| E03 认人 | E02 后约定周一 | 向林岑坦白无记忆，或冒认哥哥；均得照片，谎言后续需承认 |
| E04 维修记录 | 已完成 E03，实际持有 2 种义体 | 维修档案、高级电路 ×1；可检查旧义体，之后可选择拆解 |
| E05 身体使用合同 | 已完成 E04，实际持有 4 种义体 | 合同与账单；开放签字和批次误差对照 |
| E06 求救核心 | E05 后约定周一 | 付 200 保管核心或拒收；转交公司得 300 并签经手记录，失去核心及联络能力 |
| E07 完整录音 | 已完成 E06，实际持有 8 种义体 | 用普通电子元件 ×1 或 100 修复；读取、听供述、选择对外是否隐名；隐名获控制芯片 ×1 |
| E08 听完之后 | E07 后约定周一 | 用元件 ×1 或 100 制作完整副本并交付林岑，或拒绝；核心参与批次联络必须另问同意 |
| E09 回收报价 | 已完成 E08，实际持有 10 种义体 | 报价与电源调节组件 ×1，核对真实持有凭据；此时不强制签约或关闭调查 |
| E10 最后一笔生意 | E09 后约定周一，已完成机械飞升 | 四种互斥处置，按实际证据和分支资格提交 |

主事件按实际来访条件排队，不抢当前顾客；指定星期错过则顺延。E01／E06／E08 从首次会面起有七天答复宽限，到期过夜前要求答复，不自动代选，均有不付费退路。

录音修复、拷贝、核心交易与旧义体拆解分别消耗真实物品或资金；修复会取出原主凭据，E09 不再重复发一份。旧义体只可拆一次，得精密零件 ×1；隐名赠礼、固定主线材料与普通加工奖励分别记账。

### 隐藏调查

X01 对照相同误差；X02 启动一次观察实验并至少过一晚再读取；X03 以凭据核对门外回声。需要先检查旧义体、保留诊断材料及故障处置资格，且在结局前完成。拆毁关键实物会关闭相应分支，不能通过重复预约恢复。

### 四种结局

| 结局／稳定 ID | 处置与资格 |
| --- | --- |
| A 赎身 `legal_property` | 用原始证据及批次处置权换身体登记更正、撤销本次回收；没有新增现金赎身费，不抹除已交给林岑的副本 |
| B 复仇 `settled_account` | 报废本批保管模块和控制连接，同时失去未解身份密钥；能寄出已有可核实材料，不能凭此声称所有人已安全 |
| C 解放 `lost_and_found` | 需要真实持有核心、已交付完整副本并取得核心联络同意；由林岑核验与核心通信共同把选择交给各接收者 |
| D 逃逸 `beyond_the_world` | 需要完成三项隐藏调查并保留所需诊断／凭据；仅发送玩家自身实例片段，生成对应信件 |

一个最终权利只执行一种处置。原件、副本、密钥和诊断资料各有能力范围，不能先导出全部身份再同时执行其他结局。结局次日有按真实选择变化的后日谈；非 C 结局后单独安置核心，还需单独询问其同意。

剧情中文／英文正文以当前 `StoryCatalog`、`StoryReplies`、`StoryEvidence`、`StoryJournal` 等源码为维护对象；Git 历史保留创作过程。旧稿曾写的游戏根目录信件路径不作为正式版写入要求，当前信件由官方限定数据目录 API 处理。

## 保存、配置与当前边界

官方 `config.json` 使用 [config.example.json](../../mods/aug-mechanical-ascension/config.example.json) 中的配置；剧情开关位于官方设置。主状态当前 schema 9，剧情 contentVersion 4；生存、剧情、灰线和成就使用各自 `nicokobo.aug.*` 字符串键，物品保留 UID、生产基准与领取／交易收据。

正常保存交给原生 `SaveGame`。同槽历史读档保留原始 ModData；原生复制／导入另一个槽后，从游戏已加载的数据确认来源并在内存重绑槽位，不回读来源 ES3 文件证明发奖。本版本正常保存须保持自身一致，不另加 Demo／开发旧稿迁移。

开局、七义体、修补胶、灰线提供者、查询和固定能力已有实现。README 记载相关 Release 和定向离线检查，迁移页的七类开局物品／13 项工坊奖励原生发放结果只属于当时构建；新恢复、生产、剧情自然来访、报价、完整夜晚及人工界面仍待当前构建原生验收。本次整理未执行编译或游戏测试。
