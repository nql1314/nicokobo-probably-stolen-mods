# 原生快速回归要求

适用于已获用户授权的 Probably Stolen／Nicokobo Forge 原生测试。旧报告保留原构建、候选与测试方式。

## 窗口与运行环境

- 使用窗口模式，默认 1280×720，优先放在副屏。系统未检测到副屏时自动使用主屏。通过实际 Unity `Screen` 状态核对模式、显示器及位置。
- Steam 客户端可在启动和测试期间继续运行。使用唯一隔离游戏、`NicoT_*` 存档及 PlayerPrefs，核对副本的 `SteamManager.Initialized` 为 `false`。正式 Mod、存档、配置和信任记录按本轮保护基线核验。
- 同时核对 `globalgamemanagers` 和 `app.info` 的隔离产品名，覆盖 Unity 早期启动及中断退出。注册表按每个值的类型和原始数据字节比较；枚举顺序不属于配置内容。
- 普通信任模式测试，Developer mode 关闭。记录准确 Steam Build、游戏程序集、业务包和探针的实际候选集合。

## 全部使用生成的夹具

- 直接生成所需物品、材料、电池、液体、设备、容器、测试 NPC 和起始状态。年龄、重量、资金、日期、声望、活动、前置库存等可作为明确记录的输入夹具。
- 不为准备测试而繁殖选育、等待生长、刷经济、等待自然客户、抽取每周活动或推进完整周目。客户事务使用现有测试客户工厂或明确配置的客户夹具；剧情使用当前事件的真实测试来访入口。
- 只执行断言所必需的生产、交易、生命周期或次日结算。阈值测试可生成紧邻阈值的输入，调用真实行为跨过阈值。重复周期只用于验证累计、顺序、重复执行或各个控制分支。
- 输入夹具与受测结果分开记录：写明生成了什么、用途、UID、数量及初始标签。不得直接写入待测完成／领奖／销售结果、事务回执或通过标记来替代实际行为。
- 仍调用受测候选的真实工厂、准入、按钮／业务入口、生产委托、资源扣除与序列化实现。断言检查独立预期、资源账、物品身份、重复调用与拒绝分支。

## 保存、读档与判定

- 保存必须经过隔离环境中的原生 ES3 入口；读档使用新游戏进程。需要复制槽验证时，使用游戏的真实复制槽入口。保存和读档绑定同一候选集合。
- 参数化业务调用不代表物理鼠标手势；调用周期委托不代表完整 EndNight；隔离 Steam 触发观察不代表真实账户解锁。报告按实际执行入口表述。
- 每组使用新槽、新运行 ID 和新结果目录，检查实际探针及监督器结果。原始失败、取消和未执行记录不覆盖、不改绿；夹具准备失败与业务缺陷分别说明。
- 首轮完成后按旧报告的业务集合核对遗漏，统一进行一次夹具快速回归。只因修复、失败或具体疑点重跑相关范围，不为凑检查数反复跑全套。
- 收尾确认自建进程退出、临时配置原字节恢复、正式数据保护通过，并清理测试探针。未经授权不安装正式游戏、不发布。

夹具取得过程不当作正常玩法验证。最终覆盖范围以具体业务分母和实际结果为准，不能把检查条数或模式数当作覆盖率。
